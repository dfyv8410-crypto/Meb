# SWEB_DEPLOY — установка PHP/MySQL версии на хостинге Sweb.ru

Эта инструкция описывает развёртывание PHP/MySQL версии (PHP 7.1+ / MySQL / MariaDB) на обычном
шаред-хостинге Sweb.ru («Старт» и выше). PHP-файлы (`index.php`, `.htaccess`, `config/`, `api/`,
`installer/`, …) находятся в **корне репозитория** — папка `sweb/` была объединена в корень и
удалена. Она НЕ требует Node.js, SSH, cron или WebSockets — достаточно Apache + PHP + MySQL и FTP.

> Документы `INSTALL.md` / `DEPLOYMENT.md` в корне репозитория описывают прежнюю Node.js-версию
> (`node server.js`). Для PHP-версии используйте этот файл.

---

## 1. Подготовка базы данных (панель Sweb)

1. В панели Sweb откройте **Базы данных MySQL**.
2. Создайте базу данных (например, `meb` или `uXXXXXX_meb`).
3. Создайте пользователя базы данных и задайте пароль, выдайте ему права на базу.
4. Запишите: **хост** (обычно `localhost` или `127.0.0.1`), **имя БД**, **пользователя**, **пароль**.

Базу создавать не обязательно заранее — установщик умеет выполнять
`CREATE DATABASE IF NOT EXISTS`. Но пользователь должен иметь право создавать таблицы.

## 2. Загрузка файлов по FTP

1. Полностью загрузите **содержимое корня репозитория** (index.php, .htaccess,
   config/, api/, installer/, public/, uploads/, …) в корень вашего сайта
   (например `~/godnayamebel.ru/www/` или `public_html/`).
   ВАЖНО: загружаются файлы проекта (index.php, .htaccess, config/, api/, …),
   а не каталог репозитория как подпапка.
2. Убедитесь, что на сервер попал файл `.htaccess` (см. ниже) — при FTP-загрузке он может
   быть скрытым; проверьте, что он присутствует.

## 3. Права на запись

Установщику нужно писать в следующие каталоги и файлы:

| Путь | Что пишется |
|------|-------------|
| `config/` | `database.php`, `app.php` |
| `storage/` | `installed.lock`, бэкапы |
| `uploads/` | загружаемые изображения |

Выставьте права 755 (или 775) на эти каталоги. Файлы, которые уже внесены в эти каталоги,
должны быть доступны на запись группе/владельцу (обычно 644 достаточно).

## 4. Запуск установщика (мастер из 7 шагов)

1. Откройте в браузере `https://ваш-домен/installer`
   (алиас — `https://ваш-домен/install`).
2. **Шаг 1 — Проверка системы.** Реальные проверки PHP-окружения:
   - **PHP** — только требования PHP/MySQL приложения: версия (7.1+;
     код проверен на совместимость с PHP 7.1.33) и реально используемые
     расширения/функции: `PDO`, `PDO MySQL` (`pdo_mysql`), `mbstring`,
     `JSON`, `password_hash/password_verify`;
   - **Хранилище** — для каждого каталога `config/`, `storage/`, `uploads/`
     каталог создаётся (если отсутствует) и выполняется реальная запись
     пробного файла (не требует 777 на весь проект);
   - **MySQL/PDO** — наличие расширения `pdo_mysql`.
   Node.js **не входит** в требования — он полностью исключён из проверок
   PHP/MySQL-версии и не блокирует установку.
   Кнопка «Далее» становится доступной, только если эти требования выполнены.
3. **Шаг 2 — База данных MySQL.** Вводятся данные из панели Sweb:
   - хост (по умолчанию `localhost`), порт (3306);
   - имя БД, пользователь, пароль.
4. **Шаг 3 — Администратор + URL.** Email, имя, пароль администратора (мин. 6 символов),
   **адрес сайта** (URL). По умолчанию подставляется текущий хост; можно изменить на нужный
   домен (например `https://godnayamebel.ru`). URL нормализуется (убираются пути, слэши,
   добавляется схема http/https).
5. **Шаг 4 — Настройка сайта.** Название сайта, адрес сайта (URL) и телефон.
   Адрес можно отредактировать ещё раз перед установкой.
6. **Шаг 5 — Демо-контент.** Переключатель демо-данных (рекомендуется для первого запуска).
7. **Шаг 6 — Установка.** Мастер обрабатывает обычный PHP POST на `POST /installer/`
   без какого-либо API/Node.js:
   - проверяет подключение к MySQL и создаёт базу при необходимости,
   - записывает `config/database.php` и `config/app.php`
      (JWT-секрет — случайный, `base_url` из введённого URL или определяется из `HTTP_HOST`),
   - создаёт схему таблиц, администратора и (при выборе) демо-контент,
   - создаёт `storage/installed.lock`.
8. **Шаг 7 — Результат.** «Установка завершена» → кнопка «Войти в панель» (`/admin`).

Все проверки выполняют реальное состояние сервера (PHP_VERSION, запись в каталоги,
подключение PDO) — без подмены на `return true`, без зависимости от API и без Node.js.

Установщик — это чистый PHP-скрипт (`/installer/` → `installer/index.php`,
исполняется напрямую Apache/PHP). Шаг 1 выполняет проверки в PHP и сразу рендерит
результат в HTML — страница работает, даже если `/api/v1/*` недоступен.

Признак «уже установлено» — наличие файла `storage/installed.lock`. Для переустановки
удалите его и повторите шаги.

## 5. Проверка

- `https://ваш-домен/` — главная страница (200)
- `https://ваш-домен/installer` — установщик
- `https://ваш-домен/admin` — админка (логин/пароль, заданные в шаге 4)
- `https://ваш-домен/sitemap.xml` и `/robots.txt` — SEO-файлы
- `https://ваш-домен/api/v1/health` — JSON со статусом (БД, хранилище, кэш, бэкап)
- `php scripts/health-test.php` — автотест health-подсистемы (после загрузки файлов);
  проверяет БД, хранилище, кэш, бэкап, CRUD-зонд, `.htaccess`, а также цепочки **Медиа**
  (белый список расширений + файлы на диске), **Брендинг** (logo/favicon из настроек и
  `.ico` в whitelist/cтатике), **Баннеры** (button_url в публичном рендере, биндинг формы,
  datetime round-trip, файлы изображений активных баннеров), регрессию PHP7.1/секретов и
  **`[Structure (root, no sweb layer)]`**: 15 обязательных элементов непосредственно в корне,
  отсутствие каталога `sweb/` (на корне и вложенно), отсутствие `sweb/`-путевых ссылок в коде
  и отсутствие сегмента `/sweb` в `base_url`.
- `php scripts/production-audit.php` — API/CRUD/RBAC-аудит против живого сайта
  (health → login → RBAC → CRUD → media → settings → public site). Требует креды суперадмина
  через переменные окружения (в исходнике их нет):
  ```bash
  AUDIT_ADMIN_EMAIL=<email> AUDIT_ADMIN_PASSWORD=<pass> \
    AUDIT_BASE_URL=https://ваш-домен \
    env -i php scripts/production-audit.php
  ```
  Если переменные не заданы — выводится понятный `SKIPPED / CONFIGURATION REQUIRED`,
  код возврата 2 (не PASS 0 и не FAIL 1).
- `php scripts/e2e-test.php` — реальные сквозные цепочки через функции PHP
  (lead → notification → review → catalog → project → menu → page-builder → settings →
  users → sitemap); пишет/читает/удаляет транзакционно и не оставляет следов.
- В админке вкладка «Система» → **System Health · Диагностика**: кнопки «Быстрая проверка»
  (quick), «Полная диагностика» (full, self-HTTP + транзакционный CRUD-тест), «Экспорт отчёта»,
  списки категорий и Error Center с рекомендациями. Эндпоинт: `GET /api/v1/system/diagnostics`
  (admin+; публичным не отдаётся).
- динамические маршруты: `/p/:slug`, `/project/:slug`, `/catalog/:cat`, `/catalog/:cat/:slug`

## 6. Права на домен / HTTPS

- Sweb поддомен вида `ваш-логин.swtest.ru` и свой домен работают одинаково —
  используйте любой.
- Включите HTTPS (Sweb выдаёт сертификат на домен). Установщик сам подставляет
  базовый URL из `HTTP_HOST`.

## 7. (Опционально) Перенос существующих данных Node.js (JSON → MySQL)

Если на сайте уже были данные из старой Node-версии (каталог `storage/*.json`), их можно
перенести в MySQL. Для этого используется скрипт миграции
`scripts/migrate-json-to-mysql.php` (дополнительный, использует `collection_insert_id` +
`normalize_seed_row`).

Запуск (на хосте локально, до загрузки, либо на сервере CLI):
```bash
env -u LD_LIBRARY_PATH php scripts/migrate-json-to-mysql.php
```
Скрипт читает JSON из `../storage` (Node) и заполняет коллекции через общий механизм вставки.
Внимание: перед запуском укажите в `config/database.php` целевую базу, либо запустите
после установки через `/installer`.

> Механизм `normalize_seed_row()` отображает Node-поля (`desc` → `description`,
> `categoryId` → `category_id`) в колонки MySQL, поэтому миграция сохраняет структуру.

## 8. Android-приложение: смена адреса API

В мобильном приложении замените базовый URL API на `https://ваш-домен/api/v1`
(вместо прежнего `http://IP:3000/api/v1`). Формат ответов API сохранён:
первая строка `STATUS:200`, далее JSON-тело.

## 9. Резервное копирование и восстановление

- **В админке:** `/admin` → «Резервная копия» → «Создать» — создаётся архив
  (`GET /api/v1/backup/list`, `POST /api/v1/backup/create`).
- **Вручную:** скачайте по FTP каталоги `config/`, `storage/` и `uploads/`, а также
  сделайте экспорт БД MySQL (дамп таблиц) в панели Sweb.

Чтобы восстановить: загрузите файлы обратно, залейте дамп БД, при необходимости
удалите `storage/installed.lock` и переустановите с теми же доступными к БД.

## Короткая памятка

```
1. Создайте БД + пользователя в панели Sweb
2. Загрузите содержимое корня проекта в корень сайта (FTP), проверьте .htaccess
3. Дайте права на запись config/, storage/, uploads/
4. Откройте /installer → заполните форму (демо по желанию) → Установить
5. Вход в админку /admin   |  /api/v1/health — статус
```
